# ScreenQR website brief — 7 October 2026

## Product promise

Scan a QR code directly from your Mac screen. Click the menu-bar icon, select the code, inspect its contents, open in your default browser or copy. No need to save screenshots or use a phone.

## Search research

Observed English search results include dedicated desktop products and screenshot-upload guides. Examples: https://codexqr.com/blog/how-to-scan-qr-codes-on-mac and https://scannerqr.com/guides/how-to-scan-qr-code-on-mac . Their intent is a practical answer, not QR creation. Our landing should lead with direct screen selection rather than upload workflows. Competitor claims are not independent platform facts.

A quoted Russian Mac/screen query returned mixed irrelevant MAC-address/device results in this search sample. Do not infer low competition or low demand from that sample. Use Russian and English pages, measure real queries and impressions after indexing. No keyword volume estimates available.

## Visual direction

Light neutral background, one accent color, generous spacing, real app card as the focal point. Hero: "QR на экране? Откройте его на Mac." Subheading: "Нажмите значок, выделите код — посмотрите адрес и откройте его в браузере." Primary Download; secondary 10-second demonstration. No fake reviews, counters, badges or claims of being the only/best scanner. Do not use screenshots of private desktops in marketing; use a clean synthetic demo with an example QR.

Sections: three-step demo; supported screen/clipboard/image inputs; readable domain preview; local processing; installation and permission; FAQ; related ProfileDock tool.

## Technical SEO and performance

Static indexable HTML; unique titles and descriptions; lang + reciprocal hreflang; canonical URL for each page; descriptive crawlable anchor links; sitemap with only canonical URLs; robots; 404 status; small local assets and system fonts; no blocking analytics. Self-host image decoder if browser tool is added; never promise zero uploads until network tests pass. SoftwareApplication schema may describe real app/version/system/price; ratings must not be invented and rich results are not guaranteed.

Verify sitemap acceptance and priority URL detection in Search Console after deployment. Use real search query data to refine page copy. Report site visits, ZIP clicks, release asset downloads separately; none equals a confirmed installation.

Sources: https://developers.google.com/search/docs/fundamentals/seo-starter-guide ; https://developers.google.com/search/docs/crawling-indexing/links-crawlable ; https://developers.google.com/search/docs/appearance/structured-data/software-app

## ProfileDock cross-linking

One short Related Mac utilities section on both homepages, with a human-readable description. ScreenQR: "Work with several Chrome windows? ProfileDock gives them separate Dock shortcuts." ProfileDock: "QR code already on your screen? ScreenQR lets you read it on your Mac." Add contextual guide links only where they help the task. No mass footer keyword links and no assertion that reciprocal links automatically increase ranking.

ScreenQR can link to the existing ProfileDock site now. Add the reverse link only once the real ScreenQR URL is deployed and verified. Existing ProfileDock site not modified yet.

## Publication gates

Final name/domain availability; public GitHub repository; explicit supported architectures; signed/notarized install path or clear development-beta label; actual tested UI demo; complete app validation record. This is a researched build brief, not a deployed website or ranking prediction.
