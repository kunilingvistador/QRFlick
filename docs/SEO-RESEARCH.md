# Website research — 7 October 2026

Working name ScreenQR: check availability before public branding. No measured keyword volumes; these are search intent hypotheses.

Direct competitors:
- https://qrcodesnap.github.io/ — menu bar capture, shortcut, OCR, camera, one-click open.
- https://andrewmkhoury.github.io/qr-scanner/ — screen QR reader.
- https://www.synapsemac.com/features/qr-scanner — on-device screen scanning.

Position: screen QR reader for Mac with explicit link preview, no scan history, image/clipboard support. Do not claim unique or safer than competitors without verification.

Primary page intent: scan QR code on Mac / QR scanner for Mac / сканировать QR на Mac.
Additional useful pages: scan QR from screenshot; QR from PDF (open PDF and select code, not direct PDF import); screen recording permission; QR not detected; clipboard QR. Avoid separate duplicate pages for every phrasing.

Landing: immediately show actual screen selection -> actual result card -> Open in default browser. One download action, version/system requirements, shortcut, privacy explanation, install guide. Actual UI screenshots only after desktop verification. English and Russian pages with reciprocal hreflang and canonical URLs. Static HTML content, light assets, responsive keyboard-accessible layout. A browser image decoder can be separate tool intent, with local decoding and explicit no-upload statement once verified.

SEO: unique titles/descriptions, crawlable contextual links, sitemap, robots, correct 200/404 responses, Search Console sitemap acceptance and priority URL inspections. No invented ratings in SoftwareApplication structured data. No ranking promises.

ProfileDock linking: a small related-tools section on each homepage, useful contextual links in Mac productivity guides, shared author/about page if appropriate. Do not manufacture bulk cross-links or unrelated keyword articles. Do not modify ProfileDock until QR URLs are real and deployment verified.
